### 修复详情（第二轮 - 根本原因修复）

**问题1 - 拖拽无法摆放到位** (`App.tsx`):
- **根本原因**: handleMouseUp 中 `Math.round` 后 `clampedIndex` 限制在 `0..length-1`，且 `reorderNodes` 异步执行导致视觉不同步
- **修复**: 拖拽改回仅X轴（移除Y轴状态），handleMouseUp 直接计算 `targetIndex`，用 `splice` 重新排列数组，同步更新所有节点位置
- `handleMouseDown`: 只记录 `dragStartX` 和 `dragNodeStartX`
- `handleMouseMove`: 只更新X坐标，Y保持不变
- `handleMouseUp`: 计算目标索引 → splice 移动 → 同步更新所有节点位置（不再调用异步 reorderNodes）

**问题2 - 节点重叠遮挡** (`App.tsx` + `canvasStore.ts`):
- **根本原因**: 
  1. zIndex 为 `nodes.length - index`（最右边z-index最高），导致右边节点遮挡左边
  2. stagger 偏移让节点歪歪扭扭，不是设计意图
- **修复**: 
  1. zIndex 改为 `index + 1`（扑克牌式：index 0 的节点 z-index 最高，压在所有节点上面）
  2. 移除 `STAGGER_Y`，所有节点Y坐标统一为 `START_Y`
  3. `computePosition(index)` 只接受一个参数

**问题3 - Block 渲染与交互** (`App.tsx` NodeComponent):
- 添加 `isBlock` 判断和独立渲染分支
- Block 样式：圆角矩形(radius-2xl)、虚线边框、淡紫背景、左右端口、层数显示
- **z-index 修复**: Block 宽度 200px 大于普通节点 80px，使用 `zIndex = 100 + index`（选中时 9999）避免被后面节点盖住
- **拖拽排序修复**: `handleMouseUp` 中根据 Block 中心点计算目标索引（`centerOffset = NODE_SIZE * 2.5 / 2`）
- **选中编辑**: Block 支持 onMouseDown → selectNode → PropertyPanel 编辑 name/layerCount 参数
- AddLayerDialog 添加「容器」分类包含 block

**问题4 - 节点级验证错误** (`canvasStore.ts` + `App.tsx` + `backend/app/core/validator.py`):
- `NodeData` 添加 `validationError?: string | null`
- **后端修复**: `validator.py` 移除 `topological_sort()`，使用原始节点顺序（与前端数组索引一致），错误 `node_index` 改为 0-based
- `validateGraph` (前端): 将后端错误映射到对应节点的 `validationError`
- `NodeComponent`: 错误时边框变红、添加 `animate-flash-red` 动画、右上角显示 ⚠
- `HoverTooltip`: 错误时背景变红，显示具体错误信息
- `globals.css`: 添加 `@keyframes flashRed` 和 `.animate-flash-red`

**问题5 - 参数自动推断失效** (`canvasStore.ts` + `AddLayerDialog.tsx`):
- **根本原因**: `AddLayerDialog.handleAddLayer` 传入 `{ ...defaultParams }`，由于 `addNode` 中 `mergedParams = { ...inferredParams, ...params }`，defaultParams 会完全覆盖推断值
- **修复**: 
  1. `AddLayerDialog`: 普通层传入 `{}` 空对象，block 传入默认参数
  2. `addNode`: 改进合并逻辑，只覆盖非 undefined/空字符串的传入值
  3. `inferParamsFromPrev`: Linear 根据前驱 `out_features`/`out_channels` 推断 `in_features`，Conv2d 推断 `in_channels`

**问题6 - 激活函数集成** (`constants.ts` + `AddLayerDialog.tsx` + `PropertyPanel.tsx`):
- `DEFAULT_PARAMS.linear`: 添加 `activation: 'relu'`
- `AddLayerDialog`: 移除「激活函数」分类，linear 默认带 activation
- `PropertyPanel.renderInput`: 添加 `key === 'activation'` 分支，渲染下拉选择框

### 修复详情（第三轮）

**问题1 - Block 被盖住** (`App.tsx`):
- **根本原因**: Block 宽度 200px 大于普通节点 80px，拖到两个节点之间时，后面节点的 `zIndex = index + 1` 更高，会盖住 Block
- **修复**: Block 使用独立 z-index 计算：`isSelected ? 9999 : 100 + index`，确保 Block 始终浮于普通节点之上
- 同时 Block 视觉上移 20px (`top: node.position.y - 20`)，使其在垂直方向居中

**问题2 - Block 无法编辑** (`App.tsx` + `PropertyPanel.tsx`):
- **根本原因**: 用户误以为 Block 不支持编辑，实际上点击选中逻辑已存在（onMouseDown → handleMouseUp → selectNode）
- **验证**: Block 选中后 PropertyPanel 会显示 name 和 layerCount 参数，支持编辑
- **增强**: Block 选中时背景加深（`rgba(167, 139, 250, 0.12)`），边框加粗，视觉反馈更明显

**问题3 - 验证错误定位错误** (`backend/app/core/validator.py`):
- **根本原因**: `validate_graph` 使用 `graph.topological_sort()` 对节点重新排序，但前端节点按数组顺序排列（没有 edges 时拓扑排序可能改变顺序），导致返回的 `node_index` 与前端索引不一致
- **修复**: 
  1. 移除 `topological_sort()` 调用，直接使用 `graph.nodes`（原始顺序与前端一致）
  2. `node_index` 从 `i + 1` 改为 `i`（0-based），与前端 `nodes.map((node, idx))` 对应
