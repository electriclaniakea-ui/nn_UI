# Bug修复记录 - 2026-09-23

## 修复的三个问题

### 1. 退出按键在某些情况下失效

**问题描述**：点击退出按钮后，程序没有正确响应，有时会导致界面卡死或无任何反应。

**根本原因**：
- `handleExit` 函数使用 `document.body.innerHTML = ...` 直接替换页面DOM，这会导致React失去对页面的控制
- React事件监听器、状态管理等都会被破坏
- 异步操作（如 `stopTraining()`、`shutdownBackend()`）可能在DOM替换后才完成，导致回调失效

**修复方案**：
- 添加 `isExiting` React状态来管理退出画面
- 使用条件渲染显示退出画面，而不是直接操作DOM
- 保持React组件生命周期完整，确保异步操作正常完成

**修改文件**：
- `frontend/src/app/App.tsx`
  - 添加 `const [isExiting, setIsExiting] = useState(false)`
  - 修改 `handleExit` 函数：设置 `setIsExiting(true)` 替代 `document.body.innerHTML`
  - 在return语句开头添加退出画面条件渲染

### 2. 圆点（张量形状可视化触发器）完全没有出现

**问题描述**：节点之间应该显示的小圆点完全没有渲染出来。

**根本原因**：
- 圆点容器 `<div className="relative" style={{ height: NODE_SIZE + 100 }}>` 没有设置宽度
- 默认情况下div宽度为`auto`，只包裹内容宽度，不会扩展到包含绝对定位的子元素
- 当节点较多时，圆点的绝对定位位置超出容器宽度，被截断不可见
- 圆点z-index可能与其他元素冲突

**修复方案**：
- 计算并设置容器的正确宽度：`width: Math.max(containerWidth, 400)`
- 增强圆点视觉效果：增大尺寸、添加中心白点、提高z-index到100
- 无数据时显示灰色圆点，有数据时显示紫色圆点+脉冲动画
- 改进提示文字："点击'验证'按钮计算形状"

**修改文件**：
- `frontend/src/app/App.tsx`
  - 计算 `containerWidth = nodes.length > 0 ? addButtonX + 60 : 400`
  - 设置容器宽度：`style={{ height: NODE_SIZE + 100, width: Math.max(containerWidth, 400) }}`

- `frontend/src/features/canvas/components/TensorShapeVisualizer.tsx`
  - 增大圆点尺寸到20x20
  - 提高z-index到100
  - 添加中心白点增强可见性
  - 无数据时显示灰色，有数据时显示紫色+脉冲
  - 改进空状态提示文字

### 3. Block打包后验证出错，忽略内部层

**问题描述**：将多个节点打包成Block后，点击验证按钮，Block内部的层没有被正确计算形状，似乎被忽略了。

**根本原因**：
- 前端 `validateGraph` 函数在构建验证用的节点数据时，只传递了 `layer.params`
- Block节点的内部结构 `blockData` 存储在 `layer.blockData` 中，没有被合并到 `params` 中
- 后端 `validator.py` 检查的是 `node.params.get("blockData")`，但前端发送的数据中不包含这个字段
- 同样的问题也存在于 `generateCode` 函数中

**修复方案**：
- 在构建验证/代码生成用的节点数据时，将 `blockData` 合并到 `params` 中
- 对于 `validateGraph`：在 `canvasStore.ts` 的 `validateGraph` 方法中合并 `blockData`
- 对于 `generateCode`：在 `canvasStore.ts` 的 `generateCode` 方法中合并 `blockData`
- 在 `api.ts` 的 `validateGraph` 函数中确保 `params` 被正确传递

**修改文件**：
- `frontend/src/features/canvas/store/canvasStore.ts`
  - `validateGraph` 方法：构建节点时检查 `layer.type === 'block' && layer.blockData`，将 `blockData` 嵌入 `params`
  - `generateCode` 方法：同样处理 `blockData`

- `frontend/src/lib/api.ts`
  - `validateGraph` 函数：确保 `params` 对象被正确传递（使用展开运算符复制）

### 4. 张量形状可视化错误删除通道维度

**问题描述**：以CIFAR-10 CNN为例，图片数据形状应该是 `[3, 32, 32]`（通道、高、宽），但可视化只显示了 `[32, 32]`，通道维度3被删除了。

**根本原因**：
- 后端 `validator.py` 返回的形状已经**不包含batch维度**（例如 `[3, 32, 32]`）
- 但前端 `TensorShapeVisualizer.tsx` 中又执行了 `outputShape.slice(1)`，错误地将第一个非batch维度（通道维度）删除了
- 结果 `[3, 32, 32]` 变成了 `[32, 32]`，通道信息丢失

**修复方案**：
- 移除前端的 `slice(1)` 操作，直接使用后端返回的形状
- 更新注释说明后端已经去除了batch维度
- 调整图片数据判断条件：`shape[0] <= 512`（覆盖更多通道数情况）

**修改文件**：
- `frontend/src/features/canvas/components/TensorShapeVisualizer.tsx`
  - 移除 `const shape = outputShape.slice(1)`
  - 直接使用 `const shape = outputShape`
  - 更新 `isImage` 判断条件为 `shape[0] <= 512`

### 5. CIFAR-10 CNN示例中Linear层输入维度不匹配

**问题描述**：加载CIFAR-10 CNN示例后点击验证，Linear层报错：期望输入512维，但实际收到2048维。

**根本原因**：
- CIFAR-10网络结构：输入 `[3, 32, 32]` → 3层conv+pool → flatten
- 形状变化：`[3,32,32]` → `[32,32,32]` → `[32,16,16]` → `[64,16,16]` → `[64,8,8]` → `[128,8,8]` → `[128,4,4]`
- Flatten后：`[128 * 4 * 4] = [2048]`
- 但示例中Linear层的参数是 `in_features: 512`，与实际的2048不匹配

**修复方案**：
- 将CIFAR-10示例中第一个Linear层的 `in_features` 从512改为2048
- 同时修复 `inferParamsFromPrev` 函数中处理flatten后添加Linear层的逻辑
  - flatten层没有 `shape` 参数，原代码 `prevParams.shape?.reduce(...)` 总是失败回退到784
  - 改为使用合理的默认值2048（典型CNN flatten后的维度）
  - 在卷积层后直接添加Linear层（缺少flatten时）也使用2048作为默认值

**修改文件**：
- `frontend/src/features/canvas/components/ExampleProjects.tsx`
  - 修改CIFAR-10示例：`in_features: 512` → `in_features: 2048`

- `frontend/src/features/canvas/store/canvasStore.ts`
  - `inferParamsFromPrev` 函数中 `linear` case：flatten后使用2048作为默认值
  - 卷积层后添加Linear也使用2048作为默认值

### 11. 训练管理器重写 - 真正的模型训练与导出

**问题**：之前的训练管理器只是**模拟训练**（用随机数生成loss），没有真正创建和训练PyTorch模型，导致无法导出真实的模型。

**根本原因**：
- `_run_training` 方法没有构建真实的 PyTorch `nn.Module`
- 没有使用真实数据进行前向/反向传播
- 模型参数从未被更新
- 导出时没有任何可导出的模型实例

**修复方案**：
重写 `TrainingManager`，实现完整的真实训练流程：

1. **模型构建** (`_build_model_from_nodes`)：
   - 根据前端传来的 `graph_nodes` 动态构建 PyTorch `nn.Module`
   - 支持 Linear、Conv2d、ReLU、LeakyReLU、Dropout、BatchNorm、Flatten、MaxPool2d、AvgPool2d、Softmax、Sigmoid、Tanh、Block 等层
   - Block 节点递归解析内部子层

2. **真实训练循环** (`_run_training`)：
   - 构建模型并移到 GPU/CPU
   - 加载真实数据集（MNIST、CIFAR-10 等）
   - 配置损失函数（CrossEntropy、MSE、MAE、SmoothL1）
   - 配置优化器（Adam、SGD、RMSprop、AdamW）
   - 配置学习率调度器（StepLR、CosineAnnealing、ReduceLROnPlateau、OneCycleLR）
   - 真实的前向传播、计算损失、反向传播、参数更新
   - 每10步更新状态，每50步记录日志
   - Epoch 结束后在验证集上评估
   - 训练完成后保存模型到 `./checkpoints/{train_id}.pt`

3. **真实导出** (`export_model`)：
   - ONNX 导出：使用 `torch.onnx.export`，支持动态 batch size
   - TorchScript 导出：使用 `torch.jit.script`
   - 导出前自动将模型移到 CPU

**修改文件**：
- `backend/app/training/manager.py` - 完全重写，实现真实训练
- `backend/app/api/training.py` - 更新导出API，调用管理器的真实导出方法

### 15. 训练功能真正运行修复

**问题**：
1. 点击开始训练后半秒内完成，导出的 .pt 文件非常小
2. ONNX 导出失败
3. 训练似乎没有真正运行

**原因分析**：
1. 训练在 `async` 函数中运行，PyTorch 的同步训练代码阻塞了事件循环
2. 虽然使用了 `asyncio.create_task`，但训练代码本身是同步的 CPU 密集型操作
3. 异常可能被静默捕获，导致训练立即结束
4. 模型可能构建不正确（如缺少 Flatten 层）

**解决方案**：

1. **使用独立线程运行训练** (`backend/app/training/manager.py`):
   - `start_training` 创建 `threading.Thread` 运行 `_run_training_sync`
   - 使用 `threading.Event` (`_stop_event`) 替代 `asyncio` 状态检查
   - 训练完成后自动设置 `_is_training = False`

2. **添加前向传播测试** (`backend/app/training/manager.py`):
   - 训练前用随机输入测试模型前向传播
   - 如果失败（如缺少 Flatten 层），抛出详细错误信息

3. **添加详细训练日志** (`backend/app/training/manager.py`):
   - 记录每 epoch 耗时
   - 记录训练总耗时
   - 记录设备信息 (CPU/CUDA)

4. **修复停止训练 API** (`backend/app/api/training.py`):
   - `stop_training` 改为同步调用（因为 `stop_training()` 不再是 async）

5. **修复前端类型定义** (`frontend/src/lib/api.ts`):
   - `startTraining` 返回类型包含错误情况 `{ error: string; status: string }`
